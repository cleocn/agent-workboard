迁移阶段只允许：

```text
⬜ 待迁移分析 → 🟨 设计已确认 → 🟦 实现中 → 🟣 待双端验收 → ✅ 已完成
```

存在明确外部阻断时可使用 `⛔ 阻塞`，并填写原因和恢复条件。`已合并` 只属于来源状态，不是迁移阶段。

总体迁移阶段是由任务和验收证据派生的业务展示，不得驱动 runtime transition，也不得替代 lifecycle、queue 或 task status。子任务展示统一使用：

```text
⬜ 未开始 / 🔵 进行中 / 🟡 受阻 / 🟣 待验收 / ✅ 已完成 / ⛔ 已取消
```

emoji 仅作展示并依次映射六种 runtime task status。同一份计划最多一个 `IN_PROGRESS`。实时状态、progress、currentTask 与唯一 nextStep 由 SQLite 投影。

## 8. 自动化行为门禁

- [ ] 导航目的地与页面动作集合不相交。
- [ ] 未进入/未激活功能前业务请求为 0，首次进入只请求一次。
- [ ] 点击、滑动和返回后的选中项、筛选、滚动、分页与结果保持。
- [ ] 无权限入口隐藏，直接深链失败关闭且业务请求为 0。
- [ ] 新功能不改变既有同级页面的入口、筛选、状态和返回行为。
- [ ] 请求方法、endpoint、参数、DTO 白名单、可空字段和错误映射正确。
- [ ] 写操作具备权限、摘要、不可跳过确认、防重复提交、回读和恢复。

## 12. 完成定义

仅当以下项目全部满足时标记 `✅ 已完成`：

- Web 可见业务能力、入口层级、字段、筛选、动作、权限、状态和 API 契约等价。
- 设计复审、同类页面比较及所有批准例外有记录。
- 目标范围内环境 Schema 已核验；未包含环境的“待核验”风险被独立保留且没有被表述为已确认。
- 自动化行为门禁、目标环境真实接口、两轮视觉、响应式、Android/iOS 和全量回归均有当前源码证据。
- 清单、功能映射、本计划、问题记录与提交引用一致。
- 无凭据、敏感原始响应、缓存或构建物进入 Git。
- 所有必需子任务为 `✅ 已完成`，不存在未说明的受阻、待验收或未开始项。
- 当前任务为“无”，唯一下一步为“无”或明确的新权威记录。
